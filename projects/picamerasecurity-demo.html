A Raspberry Pi security camera that runs without the Raspberry Pi.

PiCam Security turns a Pi and a camera module into a surveillance node — continuous capture, timelapse, OpenCV filtering, and frame-diff motion alerts. The whole pipeline sits behind a small set of interfaces, so it develops, tests, and demos on any laptop against a synthetic mock camera — no hardware in the loop.

Architecture — service view roadmap

Module boundaries drawn for extraction into services.

Today it runs as one .NET process. The seams are deliberate: each capability owns its logic behind an interface, so it can be lifted into an independently deployable service that talks over a broker — a natural fit for the intermittent, event-driven traffic of a camera node (a frame captured, motion detected, an image stored).

Architecture — what runs today

Dependencies point inward, at interfaces.

Consumers depend on ICamera, ICameraController, and IImageProcessor — never on a concrete class. Swapping hardware for the mock, or adding a service host on top, touches nothing in the middle.

Capabilities

Five capture modes, one controller.

Each is a thin entry point over CameraController and ImageProcessor. Selectable from the menu at runtime.

01

Basic Capture

Single frame, encoded to JPEG at a configurable quality, written to disk with size and timestamp logged.

02

Sequence Capture

Burst of N frames with a fixed inter-shot delay; returns the list of saved paths.

03

Timelapse

Background task on a CancellationToken, capturing on an interval until stopped.

04

Image Processing

OpenCV pipeline — grayscale, Gaussian blur, Canny edge detection, resize, timestamp overlay.

05 · core feature

Motion Detection

Absolute frame difference, binary threshold, changed-pixel ratio against a tunable threshold; saves the frame and raises an event on every trigger.

The seam

One interface, two implementations — the pipeline never knows which.

// RpiCamera.Core/Interfaces/ICamera.cs
public interface ICamera : IDisposable
{
    bool Initialize();
    byte[] CaptureImage();
    Mat  CaptureFrame();
    bool IsReady { get; }
    CameraSettings Settings { get; }
}

// Startup picks the implementation once.
ICamera camera = CameraFactory.CreateCamera(settings, isMock: true);
var controller = new CameraController(camera, new ImageProcessor());

// Everything downstream is identical for mock and hardware.
controller.CaptureAndSave("CapturedImages-Basic/frame_001.jpg");
controller.CaptureSequence(count: 10, delayMS: 200, outputDir);
  • Hardware abstraction. Real Pi camera and synthetic mock implement the same ICamera; the choice is a boolean at startup.
  • Dependency inversion. Controllers and demos are constructed with interfaces, so implementations are injected and mocked.
  • Testable without hardware. 14 NUnit tests, Moq for collaborators, deterministic, runs in CI on any OS.
  • Computer vision. OpenCV via OpenCvSharp — grayscale, Gaussian blur, Canny, resize, frame-diff motion.
  • Cross-platform .NET. netstandard2.1 core library; Linux runtime for the Pi, Windows for dev.
  • Focused modules. Core / Functionality / Tests, each with a single responsibility and a clear public surface.
