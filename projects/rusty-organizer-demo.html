RustyOrganizer

Command-line tool · terminal UI · no window

A messy folder in.
An organized one out.

And you see every move before it happens. Nothing is touched until you say so.

RustyOrganizer is a Rust CLI that sorts a directory into category folders by rule, finds byte-identical duplicates, and can keep watching for new files. It has no graphical interface, so this page does the thing a screenshot can't: it runs one organize pass, step by step, and shows what the tool hands you at each stage.

Sorting is a config file

No config needed to start. The built-in rules cover the common types. Drop a config.toml next to a folder to change how it sorts, no rebuild.

# first rule that matches a file wins # use_default_rules keeps the built-ins as a fallback use_default_rules = true [[rules]] name = "Screenshots" target = "Screenshots" match = { name_contains = "screenshot" } [[rules]] name = "Photos by month" target = "Photos/{year}/{month}" match = { extensions = ["jpg", "heic"] } [[rules]] name = "Stale downloads" target = "Archive" match = { older_than_days = 90 }
name_contains

Anything with “screenshot” in the filename goes to Screenshots/, before the image rule can catch it.

{year}/{month}

Targets expand from the file’s date, so photos land in Photos/2026/08/.

older_than_days

A match can also test size ("200MB") or age. Conditions combine with AND.

It assumes it will be wrong

The whole tool is built so a bad run costs you nothing.

Preview is the default

Every run prints the full plan and waits for y. --dry-run stops there; --yes skips the prompt when you mean it.

Nothing is overwritten

A name clash at the destination becomes report (1).pdf, then (2). Two different files never collapse into one.

Every run is reversible

Applied moves are logged to .rusty-organizer/history.jsonl. organize <dir> --undo walks the last run backwards.

Watch mode won’t delete

-w keeps a folder tidy as files arrive, but only ever moves. Duplicate cleanup stays a manual, confirmed step.

How it’s built

A pipeline of pure functions with one impure end. The CLI, the TUI, and watch mode are three doors into the same room.

scannerWalks the tree with walkdir, returns path, extension, size and mtime. Unreadable entries warn, never abort.
plannerPure. Duplicate deletes first, then a classification move for every file that isn’t being deleted.
executorThe single place that touches the filesystem. Collision-safe, cross-device aware, dry-run capable.
historyAppend-only JSONL log per folder, the backing store for --undo.

The commands

One positional argument, the directory, plus flags that stack.

InvocationWhat it does
organize ~/DownloadsPreview the plan, then ask before moving anything.
organize ~/Downloads --dedupeAlso hash contents and fold duplicate copies into the plan for deletion.
organize ~/Downloads -iOpen the terminal UI to toggle changes and pick which duplicate to keep.
organize ~/Downloads --dry-runPrint the plan and exit without touching anything.
organize ~/Downloads --undoReverse the most recent run in that folder.
organize ~/Downloads -wStay running and sort new files as they land. Ctrl-C to stop.
organize ~/Downloads --config rules.tomlSort by a specific rules file instead of the auto-discovered one.

Why Rust, and what it taught me

The job is small, but it moves and deletes your files, so the cost of a bug is real. Rust’s ownership rules made the safety model easier to hold in my head: the executor owns the plan while it runs, and it’s the only code in the crate that can call fs::rename or fs::remove_file. Everything else (scanning, classifying, hashing, planning) is pure and returns data, which is also why most of the 55 tests are plain function calls with no temp directories.

The pieces I’d underestimated were the boring ones: resolving name collisions without ever overwriting, making a second run a no-op, and getting cross-device moves to fall back to copy-and-delete. The TUI was its own lesson: an event loop that has to stay responsive while never being the thing that writes to disk.

The honest tradeoff Content-hashing every size-colliding file is slower than trusting names, and the undo log only covers moves, so a deleted duplicate is gone. Both were deliberate: correct over fast for the dangerous part, and don’t pretend deletes are reversible when they aren’t.
